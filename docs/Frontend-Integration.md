Frontend Integration
After deploying the three contracts via Remix, update .env.development:

VITE_REGISTRY_ADDRESS=0x<deployed_registry>
VITE_PODS_ADDRESS=0x<deployed_pods>
VITE_MESSAGES_ADDRESS=0x<deployed_messages>
Update the ABI files (src/abi/registry.ts, src/abi/pods.ts, src/abi/messages.ts) with the actual ABIs generated by Remix compilation. Copy the ABI JSON from Remix's compilation output.

Revert contractCalls.ts back to using publicClient.readContract() and walletClient.writeContract() — remove all the rawDecode.ts manual decoding and publicClient.call() workarounds. With Solidity contracts, viem's ABI encoding/decoding works natively.

Delete src/lib/rawDecode.ts — no longer needed.

Keep src/lib/contractErrors.ts but update CONTRACT_ERRORS to match the new Solidity revert strings (e.g., require(profile.exists, "User") keeps the same error string).

Deployment Instructions
Open https://remix.polkadot.io/
Create three files: QFLinkRegistry.sol, QFLinkPods.sol, QFLinkMessages.sol
Compile each with Solidity ^0.8.20, optimizer enabled (200 runs)
Connect MetaMask to QF Network (Chain ID 42)
Deploy QFLinkRegistry first
Deploy QFLinkPods with constructor arg: registry address
Deploy QFLinkMessages with constructor args: registry address, pods address
Copy the three deployed addresses to .env.development
Copy the three ABI JSONs to src/abi/ files
Revert contractCalls.ts to standard viem readContract/writeContract
Delete rawDecode.ts
Run pnpm dev and test
Critical Notes
Each contract must stay under 48KB bytecode. If a contract exceeds this, split it (e.g., separate PodAdmin from PodCore). Keep functions minimal, avoid string operations where possible.
Use revert("User") style errors to match the existing frontend error handling in contractErrors.ts.
Use uint64 for IDs and counts, uint128 for fees, address for accounts — matching the existing ABI signatures.
The QFLinkMessages contract needs the QFLinkPods contract address to verify pod membership for sendPodMessage. Pass it as a constructor argument.
Events are optional for v1 but recommended: emit ProfileCreated(addr), emit PodCreated(podId), emit MessageSent(podId, sender), etc. viem can subscribe to these later.
