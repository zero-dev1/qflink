QDL — Quantum Design Language is the design system governing all dApps built on QF Network. It's not a component library or a color palette — it's a set of principles that every interaction, every screen, and every line of copy is measured against. The north star reference points are Linear and Stripe: premium products where every pixel feels considered.

Core philosophy: User interactions are ceremonies, not clicks. Every state change — registering a name, sending a payment, joining a pod, casting a vote — should feel intentional, weighted, and earned.

Key principles:

Earned state transitions — nothing happens instantly without acknowledgment. Multi-step flows should celebrate completion, confirm intent, and warn on irreversible actions. These are ceremonies, not form submissions.

Memory and personality — the UI remembers context and reflects it. Once a user has a .qf identity, the interface should greet them by name, show their avatar, and surface relevant state. The experience should feel like it knows you.

No dead ends — every state has a path forward. Empty states guide the user to the next action. Errors offer retry. Nothing leaves the user stranded.

No dashes in copy — commas and natural language instead. Copy should read like a person wrote it, not a database.

.qf identity integration — every dApp must integrate the QNS resolver. Wallet addresses should never be displayed as raw hex strings when a .qf name exists. Your identity should follow you across the entire ecosystem.

Visible fee and burn logic — users must see exactly what they're paying and exactly how much QF is being burned before they confirm any transaction. No hidden costs, no post-signature surprises.

Motion-rich UI — animation should be structural, not decorative. Transitions that aid comprehension, confirm state changes, and give weight to actions. Motion tells the user something happened and why it matters.

Strict visual hierarchy — typography, spacing, and color should establish clear information hierarchy. Status states should be visually distinct and consistent across the ecosystem. Every dApp should feel like it belongs to the same family at a glance.

Haptics and sound — meaningful interactions should have tactile and audio feedback. Success, error, and tap states should feel different from each other.

Toast discipline — errors don't auto-dismiss. Success feedback is brief. The component that owns the ceremony owns the feedback. Never duplicate notifications.

Mobile-first — every screen, every flow, every interaction must work on mobile before it works on desktop. Labels shouldn't break mid-word. Modals must be scrollable. Signing prompts must be readable in a mobile wallet's UI.

Non-predatory mechanics — no token launches before working product. No extractive fee models. No hidden extraction. If a dApp charges fees, the user knows exactly where that value goes.

That's QDL. Every dApp that launches through Dapp Labs is measured against these principles. It's not about matching a specific color or font — it's about meeting a standard of craft, clarity, and respect for the user that makes the entire QF ecosystem feel like one product.
